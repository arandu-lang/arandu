# Error T099: Module Requires an Operating System

A call reached `std.thread` or `std.fs` while the selected target is
freestanding. Those modules need an operating system. The `core` layer
(pure values, `Option`/`Result`, immutable strings and slices, and buffer
algorithms) remains available.

## Incorrect Code Example

```arandu
import std.thread as thread

func main(): void {
    thread.spawn(job)
}
```

Compiled with `--target=thumbv7em-none-eabihf` or
`--target=riscv32imc-unknown-none-elf`.

## Semantic Explanation

Bare-metal targets have no threads, filesystem, sockets, or wall clock. The
compiler rejects the operating-system modules at type checking instead of
emitting a host runtime into the object file. The target triple in the
message is the one the driver supplied. The compiler does not invent a chip
memory map to make the call succeed.

`std.thread` covers spawn, park, unpark, sleep, and the other functions of
that module. `std.fs` covers filesystem reads and directory listing. Wasm
targets are not bare-metal; thread operations there keep their own
unsupported-feature diagnostic.

## How to Fix

Keep the firmware logic on `core` and link the resulting object into the
existing C or C++ project:

```bash
arandu build -b llvm --target=thumbv7em-none-eabihf --emit=obj -o logic.o
```

If the program must run on a host operating system, select a host triple or
omit `--target`.
