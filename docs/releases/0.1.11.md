# Arandu 0.1.11 — relatório de promoção

**Estado:** preparação; nenhuma tag foi criada.  
**Canal:** release candidate pública do SDK Arandu v0.1.

O PR de preparação deve ser mergeado e ficar integralmente verde antes da tag.
Depois, execute na `main` atualizada:

```bash
git switch main
git pull --ff-only origin main
cargo run --locked -p xtask -- check-release-contract v0.1.11
git tag -a v0.1.11 -m "Arandu 0.1.11"
git push origin v0.1.11
```

Não mova nem force a tag. O workflow exige o S0 verde do PR mergeado e executa
somente as provas exclusivas de empacotamento, publicação e instalação pública.

## Escopo

A 0.1.11 fecha o contrato de threads da série 0.1 sem desaçucar closures no AMIR.
O recorte `move || ...` sem parâmetros e com capturas `Send` continua validado
no typechecker e rejeitado com U001, que orienta um `ThreadJob` estático. O
runtime nativo de threads permanece o caminho suportado.

A mesma preparação aposenta identificadores de socket, reactor, supervisor e
waker por geração, exige SHA-256 externo e `BLAKE3SUMS` interno antes da
publicação atômica dos instaladores, e divide o codegen LLVM, o runtime C de
tasks e o hash estrutural sem alterar IR, C ou bytes de hash.

Alvos embarcados (`thumbv7em-none-eabihf`, `riscv32imc-unknown-none-elf`),
`--emit=obj` e `core` contra `std` ficam para a 0.2.0. O compilador não adivinha
o mapa de memória do chip.
