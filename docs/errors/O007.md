# Error O007: Inconsistent Move Between Branches (Retired)

> Note: Retired in 0.3.0. Conditional moves of droppable values are now supported via runtime AMIR drop flags, and reading or moving a possibly-moved value reports `O001` (`O001UseAfterMove`).

Previously, this error occurred when a variable was moved in one branch of a conditional block (like if/else) but not in the other, leaving its state ambiguous.

## Incorrect Code Example

```arandu
x = Data {}
if condition {
    process(x) //: Moved
} else {
    // Not moved
}
y = x // Ambiguous: x might be moved here!
```

## Semantic Explanation

The compiler requires deterministic knowledge of variable initialization and move status at every instruction. Ambiguous move states are rejected.

## How to Fix

Ensure the variable is moved in both branches, or not moved in either branch, or handle it inside the conditional block:

```arandu
x = Data {}
if condition {
    process(x)
} else {
    process(x)
}
```
