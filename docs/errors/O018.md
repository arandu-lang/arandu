# Error O018: Cannot Move a Part Out of a Value with a Destructor

A type with a `@Destructor` is destroyed as a whole: its destructor runs on
the complete value. Moving a field (or a payload matched by a pattern) out of
such a value would leave the destructor an incomplete value to destroy, and
the moved part would be destroyed twice.

## Incorrect Code Example

```arandu
import std.alloc.string as strings

struct Guard { name: strings.String, id: int }

@Destructor
func Guard.destroy(self: own Guard) {}

func name(g: Guard): strings.String {
    return g.name // error O018
}
```

The rule applies wherever the part goes: a `return`, a `let`, a call
argument, or a `match` pattern that binds the field by value. It also applies
to a part of a field whose type has a destructor (`outer.guard.name`).

## Correct Code Example

Read `Copy` fields and borrow the others; neither moves anything:

```arandu
func describe(g: ref Guard): usize {
    return g.name.len() + g.id as usize
}
```

To take a part and leave the value complete, replace it:

```arandu
import std.core.mem as mem

func rename(g: mut ref Guard, name: strings.String): strings.String {
    return mem.replace<strings.String>(mut ref g.name, name)
}
```

Moving the whole value (`return outer.guard`) is always allowed.
