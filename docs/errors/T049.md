# Error T049: Invalid FFI Export

`@Export` publishes a function to the linker with a flat C symbol and the
target's C calling convention. The compiler only accepts signatures whose
representation at the binary boundary is fixed by the C ABI, so a C caller can
never disagree with the generated code about parameter or return layout.

Accepted parameters and return types:

- fixed-width integers: `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`;
- `f32` and `f64`;
- `bool`;
- raw pointers such as `ptr Frame`;
- `void` as the return type only.

Everything else is rejected at compile time.

## Target-dependent widths

`int`, `uint`, `isize`, `usize`, `float`, `char` and `str` do not have a stable
C representation across the supported targets. Choose a fixed-width type
explicitly:

```arandu
@Export
func checksum(data: ptr u8, len: u32): u32 {
    return len
}
```

## Buffers and strings

Slices (`[]T`, `mut []T`) and `str` are fat values that need a `(ptr, len)`
pair at the boundary. The C ABI classifier for exported slices is not
implemented yet, so pass the pointer and the length separately instead of
letting the compiler guess:

```arandu
@Export
func fill(buffer: ptr u8, len: u32): void {
    // ...
}
```

## Nominal types by value

Structs are not exported by value yet, even with `@Repr("C")`. Their
parameter classification (`byval`, register splitting, padding) depends on the
target ABI, and emitting the wrong shape would corrupt the boundary silently.
Pass an opaque pointer and keep the layout agreement in the header:

```arandu
public struct Frame {
    pub id: u32,
    pub weight: f32,
}

@Export
func frameId(frame: ptr Frame): u32 {
    return 0
}
```

## Shape restrictions

An exported function must be a free function with a body. It cannot be a
method, `async`, or generic: those need a monomorphized or coroutine-specific
entry point that `@Export` does not synthesize. Give the symbol an explicit
name when the C side expects a prefix:

```arandu
@Export("arandu_core_process_inputs")
func processInputs(raw: u32, mode: u32): u32 {
    return raw
}
```

Two exported functions cannot claim the same symbol; the second declaration is
rejected instead of silently replacing the first one at link time.
