# Error T102: Typed Hole

A `todo` marks an expression that has not been written yet. The program
around it is type checked as usual, and each hole is reported with the type
it must have.

## Example

```arandu
func area(width: int, height: int): int {
    let base = width
    return todo("multiply by the height")
}
```

```text
error[T102]: typed hole: expected 'int'
  note: todo: multiply by the height
  hint: fill with `base`
  hint: fill with `height`
  hint: fill with `width`
```

## Semantic Explanation

`todo`, `todo()` and `todo("reason")` are holes. The hole takes the type
expected where it stands, its _goal_: the declared return type above, an
annotation, a parameter type. Where nothing is expected (`let x = todo`), the
goal is inferred from how the rest of the body uses the value; when nothing
fixes it, the goal is shown as `_`. Because the hole has its goal's type, the
code around it reports no errors of its own.

`todo` is not a keyword. It is a name of the language prelude, so a local,
parameter, function or import called `todo` shadows it and keeps its meaning.

The diagnostic lists up to five locals and parameters in scope, declared
before the hole, whose type is the goal: the innermost scope first, the most
recent first. Each is offered as a quick fix and none is applied
automatically. When the goal is not `Copy`, filling the hole with a local
moves it, and the fix says so; the move checker still validates the program
once the hole is filled.

A hole is an error, not a warning. A program that still contains one is
checked and formatted, but it does not build, run, start tests or benchmarks,
or evaluate compile-time code that depends on it; there is no flag that turns
a hole into a runtime trap. Editors show the hole as information with an
inline hint of its goal, since an unfinished program is the expected state
while it is being written.

## How to Fix

Replace the hole with an expression of the goal type, for example with one of
the suggested fills.
